# dsp domain: design notes

Scope: a new `dsp` domain with six tools for sampled data: `dsp_filter_design`, `dsp_spectrum`, `dsp_filter_apply`, `dsp_sampling`,
`dsp_correlate`, `dsp_window`. Branch `feat/dsp-domain`, cut from main at `aa761f8`. Files touched: `eng_toolkit/domains/dsp/`,
`tests/test_dsp_*.py` + `tests/dsp_testing.py`, this folder, one README section. Nothing in `pyproject.toml`, `uv.lock`,
`tests/test_gateway.py`, the shared layer or another domain.

Ground rules followed: clean-room (textbook definitions and published design formulas only; the Kaiser and window tables are the
Oppenheim and Schafer ones, cited where used); **numpy and the standard library only at run time** (`DOMAIN.engines = ("numpy",)`, no new
dependency, no `engines.py`); scipy is imported **only in `tests/test_dsp_reference.py`**, behind `pytest.importorskip` (a test greps the
package for `scipy`, `eval`, `exec`, `compile`, `__import__`, `importlib`, `subprocess`, `pickle` and `open(`); tools never call an LLM;
**nothing the caller sends is executed** (frequencies go through one regular expression and a table of units, samples through
`json.loads`, which builds data only, or a strict line parser); every result says `review_status: "unreviewed"`; no NaN or infinity can
reach a result (`clean()` and `qty()` refuse them with `input.out_of_range`; tested through `fastmcp.Client` with strict JSON parsing).

## Input formats and limits

| What | Rule | Error |
|---|---|---|
| frequency / sample rate | text `"<number> <unit>"`, unit one of `Hz kHz MHz GHz mHz rad/s krad/s Mrad/s` (also `hz khz ghz hertz 1/s`) | no unit: `units.bare_number`; a unit of another dimension (`m`, `s`, `V`, ...): `units.dimension_mismatch`; unknown or ambiguous (`mhz`): `units.parse_error`; missing: `input.missing` |
| sample rate | positive, 1e-3 .. 1e12 Hz | <= 0: `input.invalid`; outside: `input.out_of_range` |
| filter edges | strictly inside (0, fs/2), band edges `"low, high"` increasing | 0, negative, at or above Nyquist, not increasing: `input.invalid` |
| samples (inline) | JSON list of plain numbers (no bool, string, null, nested list), finite, magnitude <= 1e100, at most 2**22 = 4 194 304 values, text at most 1e8 characters | NaN/Infinity/`1e999`/text: `input.invalid`; too many, too long, too large: `input.out_of_range` |
| samples (file) | `.csv`/`.txt` through `JobHandle.input_file` (read-directory allow-list, size cap 120 MB, copy, sha256 in `provenance.input_files`), one column of values or two columns `time,value` (seconds); numbers only, blank lines skipped; no header, no `nan`/`inf`/hex/underscore numbers | any other line: `input.invalid` with `line` in `details` and in the message; outside the allowed directories: `input.path_not_allowed`; over the cap: `input.too_large`; missing: `input.file_not_found` |
| time column | strictly increasing and uniform to 0.1 % of the step (else `input.invalid`); gives the sample rate; if `sample_rate` is also given they must agree to 0.1 % | `input.invalid` |
| IIR order | 1 .. 40 (order of the analogue prototype; a band filter has 2n poles), also for a specification that needs more | 41: `input.out_of_range` |
| FIR taps | 3 .. 4095; highpass and bandstop need an odd number (refused if given, raised by one with a warning if computed) | `input.out_of_range`, `input.invalid` |
| ripple / attenuation | ripple 1e-4 .. 20 dB, attenuation 1 .. 200 dB, attenuation > ripple | `input.invalid` |
| coefficient lists (`b`, `a`, `sos`) | finite, magnitude <= 1e12, `b` at most 4095 (FIR) or 41 with `a`, `a` at most 41, `sos` at most 40 rows `[b0 b1 b2 a0 a1 a2]` with `a0 != 0` | `input.invalid`, `input.out_of_range` |
| Welch | `segment_length` 8 .. N (else `input.invalid`), `overlap_percent` in [0, 100) (100 is `input.invalid`) | |
| recursion work | samples x sections (x2 for zero phase, order/2 for direct form) at most 4e7 steps (about 20 s of pure Python) | `input.out_of_range` |
| lag, rows | `max_lag` <= 100 000, table rows 16 .. 20 000, window length 8 .. 65 536 | `input.out_of_range` |

Long inline sample texts are not copied into `inputs.json` (length and sha256 are, so the inputs hash still identifies the data).
Tables are CSV artifacts with every number as its shortest round-trip repr (no digits lost).

## Tool by tool: what is exact, what is numerical, what is approximate

**Exact** = a closed form in double precision (rounding only). **Numerical** = floating point with the stated behaviour.
**Approximate** = a model, a table or an interpolation, with the measured error given.

### `dsp_filter_design`

* IIR by the textbook route: analogue low-pass prototype (cutoff 1 rad/s) -> frequency transformation of the roots (`s/wo`, `wo/s`,
  `(s^2+wo^2)/(bw s)`, `bw s/(s^2+wo^2)`) -> bilinear transform `z = (1+s)/(1-s)` with the analogue frequency `tan(pi f/fs)` (that is the
  prewarping). Poles and zeros are built in closed form and kept as conjugate pairs plus real roots, so the sections and polynomials are
  exactly real. Everything is **exact** up to rounding; there is no root finder in the path, so the stability check is the pole radius
  of the designed roots (`max_pole_radius`, `margin_to_unit_circle`) and does not depend on the conditioning of the polynomial.
  - Butterworth `|H|^2 = 1/(1+w^(2n))`: poles `exp(j pi (2k+n-1)/(2n))`. `cutoff` is the -3.0103 dB frequency.
  - Chebyshev I: poles `-sinh(mu) sin t_k + j cosh(mu) cos t_k`, `mu = asinh(1/eps)/n`, `eps^2 = 10^(Rp/10)-1`; DC gain `1/sqrt(1+eps^2)` for even n. `cutoff` is the passband edge (gain -Rp dB).
  - Chebyshev II: poles are the reciprocals of the Chebyshev I poles built with `mu = asinh(sqrt(10^(Rs/10)-1))/n`, zeros `j/cos t_k`, DC gain 1. `cutoff` is the stopband edge (gain -Rs dB).
  - Second-order sections `[b0 b1 b2 1 a1 a2]`: conjugate pole pairs (two real poles together), each given its nearest zeros, poles nearest the unit circle last, gain in the first section. `(b, a)` come from the same roots; the tool compares the two responses (`ba_vs_sos_max_response_error`) and warns when the direct form no longer reproduces the design (order above 8 gets a standing warning: use the sections).
* **Minimum order** from the closed forms (derived here, not copied): with `A = 10^(Rs/10)-1`, `E = 10^(Rp/10)-1` and `r` the stop-edge over pass-edge ratio of the low-pass equivalent of the prewarped edges, Butterworth `n = ceil(ln(A/E)/(2 ln r))`, Chebyshev I and II `n = ceil(acosh(sqrt(A/E))/acosh(r))`. A tolerance of 1e-9 stops `ceil(5.0000000001)` from giving 6. The passband edge is met **exactly** (loss Rp) in all three families (this is also scipy's convention for `buttord`, `cheb1ord`, `cheb2ord`), the stopband with margin; `spec_checks` lists the gain at every specified edge and whether it is met. For a **band stop** the centre of the transformation is a free parameter: the tool maximises the low-pass-equivalent ratio over it (golden section on the log of the centre between the stop edges) and never does worse than the geometric centre of the pass edges. This gives exactly scipy's orders (checked on random specifications) and edges equal to scipy's to about 1e-5 of the Nyquist frequency (scipy's own optimiser tolerance).
* Table (`filter_response.csv`): `points` rows (16 .. 20 000), linear from 0 to Nyquist, magnitude in dB floored at -300 dB, phase in degrees unwrapped along the grid (the end points where the response is exactly zero copy their neighbour's phase). **Group delay** at the edges and a few fractions of Nyquist is analytic (`Re(S_b/B) - Re(S_a/A)` per section), not a numerical derivative; on a zero of the unit circle it is 0/0 and the value is taken 1e-7 rad inside (`note` says so).
* FIR by the window method: ideal impulse response `(wc/pi) sinc(wc m/pi)` for a low pass, sums and differences for the other responses, times a symmetric window, scaled to unit gain at DC (low pass, band stop), at Nyquist (high pass) or at the band centre (band pass) — the `scipy.signal.firwin` convention, so taps agree to rounding. Taps are computed on the first half and mirrored, so `h == h[::-1]` holds **exactly**. `cutoff` is the -6 dB point; `linear_phase` reports the type (I..IV), the delay `(N-1)/2` and the check that `H(w) exp(j w (N-1)/2)` is real (`phase_residual`).
  - Kaiser: `beta = 0.1102 (A-8.7)` for `A > 50`, `0.5842 (A-21)^0.4 + 0.07886 (A-21)` for `21 <= A <= 50`, `0` below; order `M = ceil((A-7.95)/(2.285 d_omega))`, taps `M+1` (same as `kaiserord`). The textbook example (wp = 0.4 pi, ws = 0.6 pi, delta = 0.001, so A = 60 dB, d_omega = 0.2 pi) gives `beta = 5.65326`, `M = 37`, 38 taps, and the tool measures 60.35 dB of attenuation and 0.0084 dB of passband deviation.
  - Fixed windows: taps from the Oppenheim and Schafer table `d_omega = c pi/M` with c = 1.8, 6.2, 6.6, 11 (rectangular, Hann, Hamming, Blackman), promising about 21, 44, 53, 74 dB. These constants are **approximate** (a table); the measured attenuation is reported and a warning is raised when it falls short of what was asked.
  - The measured passband ripple (peak to peak and largest deviation from 1) and stopband attenuation come from a zero-padded FFT of at least 32768 points over the bands implied by the specification edges; when only a cutoff and a number of taps are given the bands are the cutoff +- half the typical transition width of that window and length (said in `measurement_bands_note`). A windowed design has one transition width: with two different transition bands the narrower sets the order.

### `dsp_spectrum`

* One-sided spectra from `rfft` of the **periodic** (DFT-even) window, so the cosine-sum windows have spectra of finite support and an on-bin tone is exact. Scalings, all **exact** for a coherent record: amplitude `c_k |X_k|/sum(w)` (this is the coherent-gain correction: the window's coherent gain is `sum(w)/N`, the tool reports it and its reciprocal), power `c_k |X_k|^2/(N sum(w^2))` and PSD `c_k |X_k|^2/(fs sum(w^2))`, with `c_k = 2` for bins that have a mirror image and 1 for DC and Nyquist. An on-bin sine of amplitude 1.5 reads 1.5 to 1e-12 with every window (observed 3e-15). Parseval: `sum(PSD) x bin width = sum((w x)^2)/sum(w^2)` (the mean square for a rectangular window), tested to 1e-12.
* Welch: segments of `segment_length` with `round(L overlap/100)` samples of overlap, `(N - noverlap)//(L - noverlap)` segments, `|X_k|^2` averaged (amplitude = square root of the average). Equals `scipy.signal.welch` (density and spectrum scalings, `detrend=False`) to 1e-11 relative. Unused trailing samples are reported.
* Peak list: local maxima within `peak_threshold_db` of the highest, parabola through `ln(amplitude)` at the three bins around each (Smith-Serra form; `offset = 0.5 (a-c)/(a-2b+c)`). **Approximate**, window dependent; measured over tone offsets 0 .. 0.5 bin at N = 1024: Hann 0.016 bin and 3.8 % of amplitude, Hamming 0.016 bin and 4.7 %, Blackman 0.007 bin and 1.1 %, rectangular 0.17 bin and 27 % (a line sharper than rounding noise is left at the bin value), flat top 0.14 bin and 1.9 %. Use Hann, Hamming or Blackman for interpolated peaks; the un-interpolated `bin_amplitude` is also returned. A non-coherent strongest tone raises a leakage warning with the scalloping loss of the window; two peaks closer than the main lobe raise a resolution warning.
* Converter metrics (`adc_metrics`), definitions are returned in `data.adc_metrics.definitions`: signal = power in the fundamental's lobe (half width 1, 2, 2, 3, 5 bins for rectangular, Hann, Hamming, Blackman, flat top, the main-lobe half widths); noise = power in every bin outside the DC lobe, the fundamental's lobe and the lobes of harmonics 2..N; SNR = signal/noise; SINAD = signal/(everything except the DC and fundamental lobes); THD = `sqrt(sum of harmonic powers)/fundamental amplitude` with harmonics folded into 0..fs/2 (`h f0` modulo the sample rate), each taken as the highest bin within +-1 of its expected position plus its lobe; SFDR = fundamental amplitude over the largest single-bin amplitude outside the DC and fundamental lobes; ENOB = `(SINAD - 1.76 - level_dBFS)/6.02` (level 0 when no `full_scale_amplitude` is given, with a warning). For a coherent record these are **exact** (SNR, SINAD, THD, SFDR tested to 1e-9 dB with known tones, for all five windows). **Limits, stated plainly:** no extrapolation to the excluded bins (the noise is low by about the excluded bins over all bins: 25 of 2049 bins for Hann at 4096 points, about 1 % or 0.05 dB); a non-coherent tone through a window is limited by the window's leakage floor (about -60 dB for Blackman: a 12-bit quantised sine reads far too low), so use coherent sampling for converter figures; a spur within a lobe width of a harmonic position is indistinguishable from the harmonic and is counted as one; the metrics are meant for a single tone.

### `dsp_filter_apply`

* The filter is given as sections, as `(b, a)` or as a design (the same parameters as `dsp_filter_design`; the design is made by calling that tool, its job id is returned, its warnings are carried over with a `design:` prefix).
* Recursion: transposed direct form II, `y = b0 x + z0; z0 = z1 + b1 x - a1 y; z1 = b2 x - a2 y` per section, in pure Python (1 000 000 samples through 4 sections take 2.5 s). A FIR (`a = [1]`) is a convolution, by FFT above 2e6 products (error about 1e-13 of the signal scale).
* **Unstable IIR filters are refused** (largest pole radius >= 1, also marginal) with the radius and the verdict in `details`, unless `allow_unstable`; the run is then refused if the output overflows (`input.out_of_range`), and zero-phase filtering of an unstable filter is refused always. The radius comes from the roots of each section's quadratic, or `numpy.roots` of `a` for the direct form (**numerical**; a high-order direct form is flagged).
* **Zero phase**: forward, then backward over the reversed output, on an odd-reflection extension (`2 x[0] - x[padlen..1]` before, `2 x[-1] - x[-2..-padlen-1]` after, `padlen = 3 max(len(a), len(b))`, or `3 (2 n_sections + 1 - ...)` for sections, as `scipy.signal.filtfilt/sosfiltfilt`) with the initial state of the steady response to a constant equal to the first sample; the extension is cut off. This is **approximate at the edges**: the backward pass starts from the last forward value as if in steady state, so a symmetric record gives a symmetric result only when the filter's response has died out inside the record (tested to 1e-12 with poles of radius < 0.5 and a 100-sample margin). Results agree with scipy's to 1e-9. The record must be longer than `padlen`. The effect on the magnitude is `|H|^2` (a sine at the -3.0103 dB frequency comes out at amplitude 1/2).
* FIR delay: reported as `(N-1)/2` samples when the taps are symmetric; `compensate_delay` advances the output by that many samples only when it is a whole number (odd N), the record being taken as zero outside; an even N gets a warning.

### `dsp_sampling`

* `alias`: `|f - fs round(f/fs)|`, folding zone `floor(f/(fs/2))`, spectrum inverted in odd zones; **exact**. `min_sample_rate`: `2 (f_max + guard)`; with `lowest_frequency` the bandpass-sampling ranges `2 f_high/n <= fs <= 2 f_low/(n-1)` for n up to `floor(f_high/(f_high-f_low))` (the 12 highest-rate ranges are listed). `quantization`: `SNR = 6.02 N + 1.76 dB` (the rounded textbook constants; the exact `20 log10(2) N + 10 log10(1.5) = 6.0206 N + 1.7609` is returned beside it, they differ by 0.0006 dB per bit); a tone below full scale lowers it by the same dB; `ENOB = (SINAD - 1.76 - level)/6.02`, the inverse. A simulated N-bit quantiser (rounding, step `2/2^N`) lands on 50.03, 62.01, 74.04 dB for N = 8, 10, 12, i.e. within 0.12 dB of the formula.
* `decimate` / `interpolate`: Kaiser-window low-pass FIR, -6 dB point at the new (decimate) or old (interpolate) Nyquist frequency, kept band `passband_fraction` (default 0.8) of that Nyquist band, alias or image bands `k fs_out +- kept band` up to fs/2, attenuation `attenuation_db` (default 60), odd length (integer delay removed), at most 4095 taps (else `input.out_of_range`). Interpolation zero-stuffs and uses gain L; output size is limited to 2**22. The measured alias or image attenuation (60.4 dB for a 60 dB design) and passband ripple (0.016 dB) are returned. **Edges:** the record is taken as zero outside, so about `delay/factor` samples at each end are affected. No polyphase structure (the filter runs at the high rate; fine up to the sample cap).

### `dsp_correlate`

* Statistics: mean, population variance, RMS, peak, peak-to-peak, crest factor (`undefined` for an all-zero record), sample variance in `data`. **Exact.**
* Autocorrelation by FFT with zero padding to at least 2N (a linear, not circular, sum), listed as the biased estimate `r[k] = c[k]/c[0]` (mean removed by default). The dominant period is read from the unbiased form `c[k]/(N-k)`: the first local maximum after the first zero crossing that reaches 0.9 of the highest, then a parabola through three lags. The **integer lag is reliable** (exactly 50 for a 50-sample sine, with noise 0.7 in amplitude 1 as well); the **refinement is approximate** because the edge terms of a finite record perturb the neighbours of the peak: +0.18 sample for 8 cycles, about 0.02 for 80. No clear peak (white noise, trend, period longer than the searched lags) is reported as `found: false` with the reason.
* Cross-correlation `c[k] = sum x[n] y[n+k]` by FFT, normalised by `sqrt(sum x^2 sum y^2)` over the whole records; a positive lag means the second record is the first delayed (`y[n] = x[n-lag]`). The integer lag is exact; the sub-sample lag is a parabola through the three values around the maximum: measured error at most 0.003 sample for Gaussian pulses of width 3 (0.0007 for width 6), 0.0016 for a Gaussian-windowed tone with 20 samples per cycle, 0.006 at 10 samples per cycle; for white-noise-like records the peak is one sample wide and the refinement is not meaningful (the integer lag is). **Mean removal biases compact pulses** (a pulse has a large mean compared with its own width): use `remove_mean=false` for pulses.
* Hilbert envelope: analytic signal by FFT (DC and Nyquist kept, positive frequencies doubled, negative dropped), modulus. **Exact for a record that holds whole periods of every component** (the FFT treats the record as periodic): an on-bin AM signal gives the modulating envelope to 1e-12; a record whose ends differ by more than 10 % of its range gets a warning because the end effects are then large.

### `dsp_window`

* Samples and properties of rectangular, Hann, Hamming, Blackman, flat top (the 5-term SRS / scipy form: 0.21557895, 0.41663158, 0.277263158, 0.083578947, 0.006947368) and Kaiser(beta), periodic or symmetric. Coherent gain, ENBW, scalloping loss, 3 dB width and highest side lobe are computed numerically (zero-padded FFT, at least 8 points per bin, then refined by the exact DTFT with golden section and bisection) and compared with the **closed form of the long-window limit** `W(d) = a0 sinc(d) + sum (a_k/2)(sinc(d-k) + sinc(d+k))` — an independent computation. For N = 1024 they agree to 1e-6 (gain), 1e-5 (ENBW), 1e-4 dB (scalloping loss), 5e-4 bin (3 dB width), 0.002 dB (side lobe). Textbook values reproduced: ENBW 1, 1.5, 1.3628, 1.7268, 3.7702 bins; scalloping loss 3.9224, 1.4236, 1.7514, 1.0989, 0.0098 dB; highest side lobe -13.26, -31.47, -42.67, -58.11, -93.0 dB; 3 dB width 0.8859, 1.4406, 1.3030, 1.6437, 3.7247 bins (rectangular .. flat top).

## Verification

* `tests/test_dsp_*.py`: every expected number is derived by hand in a comment and compared with a stated tolerance. Highlights: Butterworth gain at the cutoff -3.0103 dB to 1e-9 (every order, low/high/band); analogue poles on the left-half-plane circle of radius `tan(pi fc/fs)`; the worked specification (8 kHz, 1 kHz/1 dB, 2 kHz/40 dB) gives Butterworth n = 5.99147 -> 6 and Chebyshev 3.9081 -> 4 with edge gains reproduced from the closed forms to 1e-9; Chebyshev I ripple and the edge magnitude `1/sqrt(1+eps^2)` = 0.9440608763 to 1e-9/1e-12; sections against polynomials to 1e-10; textbook Kaiser example; hand-computed 5-tap windowed-sinc filters to 1e-14; on-bin amplitude, Parseval, THD `sqrt(a2^2+a3^2)/a1`, SNR/SINAD/SFDR/ENOB, harmonic folding; alias cases (1.3 kHz at 1 kHz is 300 Hz and many more); quantisation 6.02 N + 1.76 and a simulated quantiser; autocorrelation, cross-correlation by hand, integer and fractional delays; on-bin AM envelope; zero-phase symmetry and constant pass-through; unstable-filter refusal.
* `tests/test_dsp_reference.py` against scipy.signal (`importorskip`): `butter/cheby1/cheby2` (responses to 1e-8 and coefficients to 1e-9 at order <= 6, random designs), `buttord/cheb1ord/cheb2ord` (orders equal, edges equal to 1e-9; band-stop 2e-5), `firwin` (1e-13), `kaiserord`/`kaiser_beta`, `get_window`, `welch` (density and spectrum scalings), `correlate`/`correlation_lags`, `hilbert` (1e-12), `lfilter`/`sosfilt` (1e-12), `filtfilt`/`sosfiltfilt` (1e-9), `lfilter_zi`/`sosfilt_zi`, `freqz`/`sosfreqz`/`group_delay`.
* `tests/test_dsp_gateway.py`: registry, schemas, strict JSON, 44 hostile requests through the MCP client with the expected error family (cutoff 0 and at Nyquist, stopband edge inside the passband, order 41, 4096 taps, 5 million samples, NaN/Infinity/1e999 samples, a CSV with a text line, an unstable filter, a bad window name, negative and wrong-unit sample rates, 100 % overlap, paths outside `ENG_TOOLKIT_READ_DIRS` and `..` escapes), non-finite number parameters, and the source grep.

## What is refused (and with which family)

Unit problems `units.*`; logically wrong values (edge at or above Nyquist, stop edge inside the pass band, unknown choice, unstable filter, non-increasing band edges, an even number of taps for a highpass, a record shorter than the zero-phase extension, a constant record for cross-correlation) `input.invalid`; absurd sizes (order 41, 4096 taps, more than 2**22 samples or 1e8 characters, rates outside 1e-3 .. 1e12 Hz, a spec needing more than order 40 or 4095 taps, more than 4e7 recursion steps, a recursion that overflows) `input.out_of_range`; unreadable or forbidden files `input.file_not_found`, `input.path_not_allowed`, `input.too_large`, `input.unsupported_format`; a missing required parameter `input.missing`.

## Not done, and not verified

* Not done (by design): no adaptive filters, no wavelets, no polyphase or multirate structures beyond the integer decimator/interpolator, no elliptic filters, no Parks-McClellan/equiripple FIR, no real-time processing, no fixed-point/word-length analysis, no 2-D signals, no resampling by a rational factor, no spectrograms, no time-varying analysis, no spectral estimation beyond Welch (no multitaper, no AR models), no zero-padding option in `dsp_spectrum`.
* Approximations to keep in mind: peak-interpolation errors above; the FIR transition-width table; the sub-sample and period refinements; ENOB uses the rounded constants 1.76 and 6.02; the zero-phase edge treatment; the noise in converter metrics excludes the DC, tone and harmonic lobes without extrapolation; a spur next to a harmonic is attributed to the harmonic.
* Not verified: a real `claude -p --mcp-config` session (the tools were exercised through `fastmcp.Client` against the gateway only); behaviour above 2**22 samples (refused by design); platforms other than Windows 11; the pure-Python recursion speed on slow machines (the work limit is a step count, not a time).
