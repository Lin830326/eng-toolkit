# metrology_fit_search: design rationale

Produced under the pstack `poteto-mode` Feature playbook (architect step run by hand, see "Process notes").

## Problem

`metrology_fit_limits` answers "what are the limits of H7/g6 at 25 mm". An engineer usually starts from the other end: "I need 7 to 41 micrometres of clearance at 25 mm, which standard fit gives that". Today the agent would have to guess codes and call `fit_limits` repeatedly. The reverse lookup is a pure search over the same tables, so it needs no new data.

## Usage (caller's view)

```text
metrology_fit_search(nominal="25 mm", min_clearance="0 mm", max_clearance="0.05 mm")
  -> candidates (best first): H7/g6 (7..41 um), H7/h6 (0..34 um)
metrology_fit_search(nominal="25 mm", min_clearance="-0.05 mm", max_clearance="-0.001 mm")
  -> H7/s6 (-48..-14 um), H7/p6 (-35..-1 um)     (negative clearance = interference)
metrology_fit_search(nominal="25 mm", min_clearance="0.007 mm", max_clearance="0.041 mm", basis="shaft")
  -> G7/h6
```

The window is the clearance the assembly can tolerate. A fit qualifies when its minimum clearance is at least `min_clearance` and its maximum clearance is at most `max_clearance`. Clearance is hole size minus shaft size, so interference is negative, as in `metrology_fit_limits`.

## Shape

* `fit_search.py` (pure, no MCP, no pint): fit-set tables, candidate generation, window test, ranking. It calls `iso286.fit_limits` for every limit, so there is one owner of the ISO 286 numbers.
* `tools.py`: one new tool that parses the strings and shapes the contract.
* Fit sets are data, not branches. `PREFERRED` is two literal lists of the ten preferred fits for hole basis and shaft basis (ISO 286 / ANSI B4.2). `common` is generated by one rule: hole basis pairs each hole `H6..H11` with shaft letters `c d e f g h js k m n p r s t u` at grade equal to the hole grade or one finer; shaft basis mirrors it. Classes the standard does not define at the size are skipped.
* Ranking (best first): larger tolerance sum (cheaper to make), then fit centre nearest the window centre, then list order. Each candidate carries `preferred: true/false`.
* When nothing fits, the tool succeeds with an empty list and a `nearest` list of the closest misses with how far each is outside the window, so the agent can relax the window instead of guessing.

## Alternatives considered

1. **Search every letter and grade.** Complete, but returns dozens of unusual fits an agent would then have to filter. Rejected for the `common` set, which is a documented rule, and `preferred` for the default.
2. **Only the 20 preferred fits.** Honest default, but fails for windows between the preferred steps. Kept as the default; `common` covers the rest.
3. **Solve for tolerance instead of listing fits** (return required hole and shaft tolerances). Different question, and it cannot name a standard fit. Out of scope.

## Tradeoffs accepted

* We accept ranking by tolerance sum (manufacturing cost proxy) in exchange for one deterministic order. It is not a design judgement about which fit suits the application.
* We accept pairing hole grade with shaft grade `g` or `g-1` only. Other pairings exist but are rare.
